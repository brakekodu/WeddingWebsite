# Invitation system

## Concepts

- **Household** — who lives together / gets mail together. Grouping only.
- **Invitation** — one issued invitation. Owns a **token**, an **RSVP code**, and
  (derived) a **QR code**. Covers one or more guests via `invitation_guests`.
- Usually one household ↔ one invitation, but nothing assumes it: split a
  household across invitations or combine guests from several households.

## Credentials

|              | Token                                                        | RSVP code                                                            |
| ------------ | ------------------------------------------------------------ | -------------------------------------------------------------------- |
| Purpose      | In the QR / link: `/i/{token}`                               | Typed at `/rsvp` if the QR can't be scanned                          |
| Format       | 24 chars base64url (`A–Z a–z 0–9 - _`)                       | 8 chars from `ABCDEFGHJKMNPQRSTUVWXYZ23456789`, shown as `ABCD-2345` |
| Entropy      | 144 bits                                                     | ~39.6 bits, plus a global throttle                                   |
| Generated by | Postgres `extensions.gen_random_bytes` (CSPRNG) in a trigger | same (rejection sampling, no modulo bias)                            |
| Uniqueness   | unique constraint + retry loop                               | unique constraint + retry loop                                       |

Neither is derived from any database ID. Guests may type the code in any case,
with or without the dash.

## The canonical URL and the domain

```
QR content = APP_BASE_URL + "/i/" + token
```

- Only the **token** is stored. `APP_BASE_URL` is configuration, so the
  production domain can be chosen later without regenerating any token.
- `APP_BASE_URL` must be an origin (`https://example.com`), no path or trailing slash.
- While it is `localhost`, an IP address, `http://`, or a preview host
  (`*.vercel.app`, `*.pages.dev`, `*.workers.dev`), it is **provisional**: the
  admin shows a banner, prints are watermarked **PROOF**, and "Mark final print
  done" is refused.
- **Do not print production invitations until `APP_BASE_URL` is the final domain.**

## Lifecycle

```
draft ──lock──► locked                 (one-way; token + code immutable)
  │               │
  └──void──► void ◄┘   (link and code stop working; restorable)

print_status: not_printed → proof_printed → printed
```

- **Draft**: guests can be changed; credentials can be regenerated
  ("Regenerate link and code") — the old link stops working immediately and any
  `proof_printed` status resets.
- **Locked**: credentials permanent. Do this before final printing.
- **Void**: `get_invitation` and `resolve_rsvp_code` treat it as nonexistent.
- **Printed** requires: locked + QR validation passed (DB-enforced) + current
  URL validated + non-provisional domain (app-enforced).

## QR generation

`src/lib/invitations/qr.ts` builds one QR matrix (error correction M, 4-module
quiet zone) and renders it two ways from the same modules:

- **SVG** for the admin page, the print proof, and `qr.svg` download (vendor-neutral artwork).
- **RGBA raster** for decoding during validation.

## QR validation

"Validate QR" (`src/lib/invitations/validation.ts`) proves:

1. **QR exists** — a matrix is generated for the expected URL.
2. **QR decodes** — jsQR decodes the rendered modules.
3. **Canonical base URL** — decoded URL is exactly `APP_BASE_URL/i/{token}` (origin, path, no query).
4. **Token matches** — decoded token equals the invitation's token.
5. **Token resolves to this invitation** — admin lookup by token returns this invitation's ID.
6. **Resolves to the expected guests** — the _public_ `get_invitation` RPC (the
   same call a guest's phone triggers) returns exactly this invitation's guests,
   and there is at least one.

The result (status, time, exact URL, per-check details) is stored on the
invitation. Status is shown as **stale** if `APP_BASE_URL` changed since, and is
reset automatically when guests change or credentials rotate.

- **Test QR** runs the same checks without saving.
- **Validate all** (Invitations page) validates every non-void invitation.
  Bulk printing (later phase) must refuse to proceed while any invitation is
  failed, stale, or not validated.

Also do a physical test: print a proof and scan it with a phone that can
reach `APP_BASE_URL`.

## Single-invitation print

`/admin/invitations/{id}/print` renders a plain 5×7 in card: names, QR code,
the `/rsvp` fallback URL, and the RSVP code. It uses the browser's print
dialog (`@page size: 5in 7in`), so it works with any printer or "Save as PDF",
and is not tied to a vendor. "Record proof printed" tracks proof rounds.
Final artwork, PDF export, and mass printing come later, built on the same QR
and validation code.

## Changing the production domain later

1. Set `APP_BASE_URL` to the new origin and redeploy.
2. Every validation shows as stale → run **Validate all**.
3. Print and scan a proof. Tokens never change.
