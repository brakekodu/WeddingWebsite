# Project rules (Brake Wedding Platform)

Read `README.md` and `docs/` first. Security invariants — do not break these:

- **RLS on every table**, created in the same migration as the table. Never add
  a policy for `anon` on wedding tables; guests use the RPCs in
  `supabase/migrations/*_guest_rpc.sql` only.
- Admin = authenticated **and** in `admin_users`. Every admin Server Action goes
  through `runAdminAction()` (`src/lib/admin/actions.ts`).
- Never expose `SUPABASE_SECRET_KEY`/R2 keys to client code or `NEXT_PUBLIC_*`.
  `src/lib/supabase/admin.ts` is server-only and unused at runtime in Phase 1.
- Invitation tokens/codes are generated by the database only; never derive them
  from IDs; locked tokens are immutable (trigger-enforced).
- Invitation URLs are always `APP_BASE_URL + /i/{token}` (`buildInvitationUrl`); never hard-code a domain.
- Schema changes: new migration file (never edit a pushed one), update
  `src/lib/supabase/database.types.ts`, add tests in `tests/db/`.
- Never hard-code events or meal names in application logic.
- Run `npm run check` before committing.
